# LLM Proxy v0.2.0 Preview

## Download and install

Choose the installer for your computer. No terminal, Node.js, or Rust is required.

| Computer                             | Download                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Apple Silicon Mac, macOS 13 or newer | [Download DMG](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.0/LLM-Proxy-0.2.0-macOS-Apple-Silicon.dmg)     |
| Intel Mac, macOS 13 or newer         | [Download DMG](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.0/LLM-Proxy-0.2.0-macOS-Intel.dmg)             |
| Windows 11 x64                       | [Download setup EXE](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.0/LLM-Proxy-0.2.0-Windows-x64-Setup.exe) |

On Mac, open the DMG and drag **llm_proxy** into **Applications**. On Windows, run the setup EXE; installation may download Microsoft WebView2 if it is missing. Use these installer assets, rather than GitHub's developer-only source archives.

## Changes in this release

- The proxy runs in a separate background worker. Closing or quitting settings leaves the proxy and active requests running; reopen the app to manage it.
- Background startup is configured automatically after setup. Only the worker starts after sign-in; the settings app stays closed. The Start at login checkbox and resident tray have been removed. macOS uses a per-user LaunchAgent; Windows uses a per-user logon task. Startup requires signing in, rather than running before login.
- **Set up HTTPS and trust certificate** combines certificate creation and trust setup in one action. The operating system may still request approval.
- macOS setup explains **Always Allow** and provides **Check saved-key access** to handle Keychain approval during setup.
- Settings and the worker communicate through a restricted current-user socket or named pipe. The worker has no webview dependency.

## Upgrade from v0.1.0

Quit the old app once before replacing it. Existing settings, provider keys, and HTTPS certificates are retained; the old app startup entry is migrated automatically. On Mac, the new worker may need a new **Always Allow** approval for each configured provider key and the HTTPS private key. Run the installed copy from Applications. Ad-hoc signed updates may require renewed approval later.

The older Word installation guide shows the previous two-button HTTPS setup and tray behavior. Use the [current setup instructions](https://github.com/rickie-austin-114/llm_proxy/blob/v0.2.0/README.md#install-and-configure) for this release.

## Configure Claude in PowerPoint

1. Open **llm_proxy**, enter your provider API key, and save settings. Keep the Claude upstream endpoint `https://api.servicesessentials.ibm.com`, or the OpenAI endpoint `https://api.servicesessentials.ibm.com/v1`, unless your service owner supplies another endpoint.
2. With the proxy stopped, open **Office gateway HTTPS** and select **Set up HTTPS and trust certificate**. Approve any OS prompt, then start the proxy and fully restart PowerPoint.
3. In the Claude add-in, choose **Cloud provider or gateway**, then **LLM Gateway**. Enter `https://localhost:8788/claude` and the same Claude API key saved in llm_proxy. There is no separate local token.

On macOS, approve background activity in System Settings if requested. If startup has been disabled in the OS, the app respects that choice; background startup status appears in settings.

## Preview limitations

Mac applications have an ad-hoc signature without Apple Developer ID signing or notarization. The Windows installer has no publisher signature. Operating-system or organization policies can block these development packages; signed production installers are pending.

Each computer needs its own local HTTPS setup. Installer signatures and local certificate trust are separate. macOS Keychain approval is remembered by the OS; a locked Keychain can still require unlocking.

Automated build/test results do not establish clean-account install/upgrade/uninstall, sign-in/reboot behavior, native approval flows, or a live Office/provider connection. The required combined background RAM below 200 MB, ideally below 100 MB, remains unmeasured. See [validation notes](https://github.com/rickie-austin-114/llm_proxy/blob/v0.2.0/VALIDATION.md) for completed checks and pending acceptance work.

`SHA256SUMS.txt` contains checksums for the three installers.
