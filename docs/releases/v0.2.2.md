# ICA proxy v0.2.2 Preview

This preview adds guided first-run setup, optional setup dismissal, and macOS background-startup recovery. It also repairs incomplete macOS bundle signatures and verifies the app and worker inside each Mac installer.

## Download and install

Choose the installer for your computer. No terminal, Node.js, or Rust is required.

| Computer                             | Download                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Apple Silicon Mac, macOS 13 or newer | [Download DMG](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.2/ICA-Proxy-0.2.2-macOS-Apple-Silicon.dmg)     |
| Intel Mac, macOS 13 or newer         | [Download DMG](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.2/ICA-Proxy-0.2.2-macOS-Intel.dmg)             |
| Windows 11 x64                       | [Download setup EXE](https://github.com/rickie-austin-114/llm_proxy/releases/download/v0.2.2/ICA-Proxy-0.2.2-Windows-x64-Setup.exe) |

On Mac, open the DMG and drag **ICA proxy** into **Applications**. On Windows, run the setup EXE; installation may download Microsoft WebView2 if it is missing. Use these installers; GitHub's source archives are for developers.

## Changes in this release

- New installations get a resumable setup wizard for one provider key, trusted local HTTPS, and background startup. Existing installations retain their settings and skip the wizard.
- **Skip setup** saves entered details and opens settings. Saved keys and certificate progress are retained; endpoint-only edits do not create a configured key. Skipping is remembered, and **Resume setup** returns to the wizard. Skipping does not start a stopped proxy or newly enable background startup.
- macOS background approval has an explicit Login Items settings action and a status recheck. Missing-service recovery validates the bundled worker and LaunchAgent, attempts registration once, and verifies the result. OS-disabled startup and reset preferences remain respected.
- Startup failures distinguish approval, missing-service, installation, and signing problems with sanitized diagnostics. Checking a running proxy asks before the worker handoff can interrupt requests.
- macOS packaging now explicitly signs the complete app bundle and embedded worker. Automatic build checks reject incomplete linker signatures, missing resource seals, altered app contents, and installers that do not match the verified build.

## Upgrade and configure

Quit ICA proxy settings, replace the installed app using the appropriate installer, and reopen the installed copy. Keep your saved provider keys, settings, and HTTPS identity; do not use **Reset data / prepare to uninstall** for this update. macOS may request renewed **Always Allow** approval for the worker after its executable changes.

If an older Mac build reports **SMAppService error 3**, replace the entire app in Applications with this verified installer before retrying **Check background startup**. A valid ad-hoc signature repairs bundle integrity; native background registration still requires platform acceptance testing.

For new installations, follow the wizard. Claude for Office uses `https://localhost:8788/claude` and the same Claude API key saved in ICA proxy. Default upstream endpoints remain `https://api.servicesessentials.ibm.com` for Claude and `https://api.servicesessentials.ibm.com/v1` for OpenAI. Each computer needs its own HTTPS setup.

Closing or quitting settings leaves the proxy worker running. Reopen ICA proxy from Applications or the Start menu to manage it. See the [installation instructions](https://github.com/rickie-austin-114/llm_proxy/blob/v0.2.2/README.md#install-and-configure) for setup, approval recovery, and upgrades from llm_proxy. The older Word guide shows the previous setup and tray behavior.

## Preview limitations

Mac apps use ad-hoc signing without Apple Developer ID signing or notarization. The Windows installer has no publisher signature. Operating-system or organization policies may block these development packages; signed production installers are pending.

Automated tests and package verification do not establish clean-account install/upgrade/uninstall, native credential and certificate prompts, native background registration, sign-in/reboot behavior, or a live Office/provider connection. Combined background RAM below 200 MB, ideally below 100 MB, remains an unmeasured release gate. See the [validation notes](https://github.com/rickie-austin-114/llm_proxy/blob/v0.2.2/VALIDATION.md) for completed checks and pending acceptance work.
